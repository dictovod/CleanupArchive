## О проекте

CleanupArchive — консольная утилита на PowerShell, которая находит и
безопасно удаляет накопившийся "мусор" на диске: временные файлы,
кэши браузеров, кэш обновлений Windows, дампы аварийных сбоев и другие
восстанавливаемые данные, — а также умеет выполнять базовое обслуживание
системы (очистка хранилища компонентов через DISM, проверка целостности
системных файлов через SFC).

Проект создавался с одним принципом на первом месте: **лучше пропустить
файл, чем удалить что-то важное**. Каждое удаление проходит через единую
функцию безопасности (`Remove-ItemSafely` в `modules\Utils.psm1`),
которая сверяет путь со списком защищённых системных каталогов и
разрешённым корнем конкретной задачи, не переходит по junction/symlink,
а занятые или изменившиеся файлы отмечает как безопасно пропущенные,
вместо того чтобы считать их критической ошибкой.

## Возможности

- Автоматический запрос прав администратора (UAC).
- Определение Windows 10 / 11, сборки, редакции, архитектуры, типа
  диска (SSD/HDD), общего/занятого/свободного места.
- Отображение состояния диска **до** и **после** очистки и итоговой
  освобождённой суммы.
- Текстовый индикатор прогресса `[██████████░░░░░░░░]  53%` по каждой
  задаче.
- Очистка:
  - `%TEMP%` пользователя и `Windows\Temp`;
  - кэша Prefetch (опционально, выключено по умолчанию);
  - кэша загрузок Windows Update (`SoftwareDistribution\Download`);
  - кэша Delivery Optimization;
  - кэша шейдеров DirectX (в т.ч. NVIDIA/AMD, если присутствуют);
  - кэша эскизов (миниатюр) и значков Проводника;
  - **кэша браузеров** — Chrome, Edge, Firefox, Opera, Brave, Vivaldi.
    Удаляется только папка дискового кэша; история, пароли, куки и
    закладки не читаются и не изменяются;
  - отчётов об ошибках Windows (WER), Minidump, `MEMORY.DMP`,
    LiveKernelReports;
  - кэша Windows Defender (опционально и выключено по умолчанию; только
    `Scans\History\CacheManager`, без отключения защиты и изменения прав);
  - кэша Microsoft Store (через штатный `wsreset.exe`);
  - кэша шрифтов (служба Windows Font Cache);
  - заведомо безопасных временных файлов установщика (`*.msi`, `*.msp`,
    `MSI*.tmp`) — папка `Windows\Installer` не трогается никогда;
  - старых лог-файлов Windows (CBS.log, DISM.log, setupapi-логи,
    логи Panther);
  - временных файлов и логов OneDrive и Microsoft Office (папка
    `UnsavedFiles` с несохранёнными документами не трогается);
  - корзины.
- Очистка хранилища компонентов через `DISM /StartComponentCleanup`
  (включено по умолчанию, отключается в config.json), опционально
  `/RestoreHealth`.
- Опциональная проверка `SFC /scannow`.
- Опциональная полная очистка журналов событий Windows (`wevtutil`),
  выключенная по умолчанию. Она удаляет все события выбранных каналов,
  а не только старые; журнал **Security** всегда исключён.
- Опциональный сброс кэша DNS.
- Опциональная (по умолчанию выключена) очистка старых точек
  восстановления с сохранением заданного числа последних — через
  официальный VSS/CIM API, без прямого доступа к
  `System Volume Information`. Затрагиваются только теневые копии с
  признаком `Context=ClientAccessible` — именно так Windows помечает
  копии, созданные System Restore; теневые копии стороннего ПО
  резервного копирования этим фильтром не задеваются.
- Подробный текстовый журнал каждого запуска в `logs\`.
- Автоматический HTML-отчёт в `reports\` (тёмная тема, сводка +
  таблица по каждой задаче).
- Все настройки — в `config.json`, без пересборки и правки кода, либо
  через веб-интерфейс настроек (`Settings.bat`).

## Предпросмотр и подтверждение

Cleanup.ps1 **всегда** сначала выполняет холостой прогон всех задач —
ничего не удаляя, только считая, что было бы удалено — и лишь потом
спрашивает:

```
Предпросмотр — будет удалено
  Файлов (оценка)      : 4218
  Папок (оценка)       : 37
  Освободится (оценка) : 1.24 ГБ

Выполнить очистку по этим данным? (Y/N)
```

Реальное удаление начинается только после ответа `Y`/`Д`. Предпросмотр
формирует неизменяемый план с SHA-256-идентификатором. После подтверждения
разрешено удалить только уже показанные пути и выполнить только уже
запланированные системные действия. Новый или изменившийся объект
безопасно пропускается. Для папок сравнивается отпечаток содержимого, а
junction, символические ссылки и другие reparse points не обходятся.

Два флага командной строки для сценариев без диалога:

| Флаг | Поведение |
|---|---|
| `Cleanup.ps1 -WhatIf` | Только предпросмотр. Ничего не удаляется, подтверждение не запрашивается, скрипт завершается сразу после показа сводки. |
| `Cleanup.ps1 -Force`  | Без вопросов формирует план в памяти и выполняет очистку. Автоматически включает `-NonInteractive` и `-NoPause`; предназначен для уже повышенной задачи планировщика. |
| `Cleanup.ps1 -NonInteractive` | Запрещает запрос UAC и любой ввод. Для реальной очистки требует также `-Force`; без прав администратора возвращает код 5. |
| `Cleanup.ps1 -NoPause` | Не ждёт Enter перед завершением. |
| `Cleanup.ps1 -CreateSupportBundle` | После запуска создаёт обезличенный диагностический ZIP в `support\`. |

Коды завершения для автоматизации:

| Код | Значение |
|---:|---|
| `0` | Все задачи завершены без критических ошибок; безопасные пропуски допустимы. |
| `1` | Есть хотя бы одна критическая ошибка задачи, отчёта или запрошенного диагностического пакета. |
| `2` | Пользователь отменил запуск либо автоматическая очистка запрошена без `-Force`. |
| `5` | В режиме без взаимодействия отсутствуют права администратора. |

Учтите: DISM и SFC не имеют собственного "холостого" режима на уровне
Windows, поэтому их объём заранее не оценивается. Размер журналов событий
оценивается перед подтверждением, но активные каналы могут получить новые
записи до выполнения. Точная сумма высвобожденного места всегда видна в
итоговой сводке после реального запуска.

## Веб-интерфейс настроек

Раз настроек стало много, `config.json` необязательно редактировать
руками. **`Settings.bat`** поднимает локальную веб-страницу с
переключателями для каждой опции:

1. Запустите `Settings.bat`.
2. Автоматически откроется браузер на `http://127.0.0.1:8791/`
   (сервер слушает только сам компьютер — `127.0.0.1`, недоступен по
   сети и не запрашивает прав администратора).
3. Настройте переключатели, нажмите «Сохранить настройки» — они сразу
   пишутся в `config.json`.
4. Кнопки «Запустить CleanupArchive» и «Только предпросмотр» открывают
   `Cleanup.ps1` в обычном консольном окне — с тем же самым запросом
   прав, предпросмотром и подтверждением, что и при запуске `Start.bat`
   напрямую. Страница ничего не удаляет сама — она только редактирует
   config.json и запускает уже проверенный консольный сценарий.
5. Внизу страницы — список последних HTML-отчётов, кликабельный.

Реализовано на `System.Net.HttpListener` — это часть .NET, входящая в
Windows, поэтому никаких дополнительных программ (Node.js, Python и т.п.)
устанавливать не нужно. Закрыть сервер — закрыть окно PowerShell или
нажать в нём Ctrl+C.

## Что НЕ удаляется

Список защищён на уровне кода (`$Script:ProtectedPaths` в
`modules\Utils.psm1`) и проверяется перед **любым** удалением, независимо
от того, какой модуль его вызвал:

```
WinSxS, System32, SysWOW64, Fonts, Installer, Boot, System Volume
Information, $Recycle.Bin, Recovery, EFI, WindowsApps, Microsoft Edge
(программные файлы), Windows Defender (программные файлы и платформа),
WindowsPowerShell, Microsoft.NET, корень любого диска (C:\ и т.п.)
```

а также данные, к которым утилита в принципе не обращается: история
браузеров, пароли, куки, закладки, документы пользователя, файлы в
папке OneDrive и несохранённые файлы Office.

## Установка и запуск

1. Скачайте и распакуйте архив `CleanupArchive_v1.2.1.zip` в папку, куда у
   текущего пользователя есть права записи: рядом создаются журналы,
   отчёты и диагностические пакеты.
2. Запустите **`Start.bat`** двойным щелчком.
3. Подтвердите запрос UAC — большинству операций очистки нужны права
   администратора.
4. Дождитесь завершения (индикатор прогресса и статус выводятся в
   консоли). По окончании нажмите Enter, чтобы закрыть окно.

Также можно запустить напрямую через PowerShell, в том числе с флагами
`-WhatIf` (только предпросмотр) или `-Force` (без диалога подтверждения —
см. [Предпросмотр и подтверждение](#предпросмотр-и-подтверждение)):

```powershell
powershell -ExecutionPolicy Bypass -File .\Cleanup.ps1
powershell -ExecutionPolicy Bypass -File .\Cleanup.ps1 -WhatIf
powershell -ExecutionPolicy Bypass -File .\Cleanup.ps1 -Force
powershell -ExecutionPolicy Bypass -File .\Cleanup.ps1 -Force -CreateSupportBundle
```

Чтобы настроить `config.json` через браузер вместо ручного редактирования
JSON — запустите **`Settings.bat`** (подробности в разделе
[Веб-интерфейс настроек](#веб-интерфейс-настроек)).

## Настройка (config.json)

```json
{
  "RunSFC": false,
  "RunRestoreHealth": false,
  "RunComponentCleanup": true,
  "CleanPrefetch": false,
  "FlushDNS": true,
  "CreateHTMLReport": true,
  "VerboseLog": true,
  "CleanDefenderCache": false,
  "CleanEventLogs": false,
  "CleanRestorePoints": false,
  "KeepRestorePoints": 3
}
```

| Параметр             | По умолчанию | Описание                                                                 |
|-----------------------|:---:|---------------------------------------------------------------------------|
| `RunSFC`              | `false` | Запускать `sfc /scannow` (проверка целостности системных файлов).     |
| `RunComponentCleanup` | `true`  | Запускать `DISM /StartComponentCleanup` (освобождает место после накопившихся обновлений). |
| `RunRestoreHealth`    | `false` | Запускать `DISM /RestoreHealth` (может скачивать данные через Windows Update). Работает только вместе с `RunComponentCleanup = true` — это его подопция, а не независимая задача. |
| `CleanPrefetch`       | `false` | Очищать кэш Prefetch.                                                  |
| `FlushDNS`            | `true`  | Сбрасывать кэш DNS-клиента.                                            |
| `CreateHTMLReport`    | `true`  | Формировать HTML-отчёт в `reports\`.                                   |
| `VerboseLog`          | `true`  | При `true` в структурированный `.jsonl`-журнал попадают все информационные строки; при `false` — только сводки по задачам, предупреждения и ошибки. Текстовый `.log` и консоль подробность не меняют. |
| `CleanDefenderCache`  | `false` | Пытаться очистить только `Scans\History\CacheManager`; защищённые файлы безопасно пропускаются. Защита Defender не отключается. |
| `CleanEventLogs`      | `false` | Полностью очищать выбранные журналы событий через `wevtutil`; Security всегда исключён. Это не удаление только старых записей. |
| `CleanRestorePoints`  | `false` | Удалять точки восстановления старше `KeepRestorePoints` последних.     |
| `KeepRestorePoints`   | `3`     | Сколько последних точек восстановления сохранять при включённом `CleanRestorePoints`. |

Если `config.json` отсутствует или повреждён, используются безопасные
значения по умолчанию, указанные выше, — программа не прерывает работу.

## Логи, отчёты и диагностика

Каждый запуск создаёт два журнала, а реальный запуск при включённой опции
`CreateHTMLReport` — ещё и HTML-отчёт. Всё хранится только на вашем диске,
рядом со скриптом:

- **`logs\cleanup_ГГГГ-ММ-ДД_ЧЧ-мм-сс.log`** — человекочитаемый
  построчный журнал: что удалено, что пропущено, какие возникли ошибки,
  сколько места освобождено по каждой задаче.
- **`logs\cleanup_ГГГГ-ММ-ДД_ЧЧ-мм-сс.jsonl`** — тот же журнал в
  структурированном виде (JSON Lines: одна JSON-запись на строку), плюс
  версия CleanupArchive, версия PowerShell, длительность каждой задачи в
  миллисекундах и, для ошибок, полный тип исключения и стек вызовов, а
  не только текст сообщения. Формат специально рассчитан на то, чтобы
  его было легко разобрать программно — например, если что-то пошло не
  так, этот файл гораздо удобнее приложить к сообщению об ошибке или
  вставить в чат с ИИ-ассистентом для разбора, чем текстовый лог.
  Опция `VerboseLog` в config.json включает/выключает запись обычных
  информационных строк в этот файл; сводки по задачам и все
  предупреждения/ошибки пишутся в него в любом случае.
- **`reports\report_ГГГГ-ММ-ДД_ЧЧ-мм-сс.html`** — наглядный отчёт с
  общей сводкой, статусом каждой задачи, числом безопасных пропусков и
  раскрываемыми подробностями ошибок.

Каждая задача сохраняет в JSONL отдельное событие `task_result`:
удалённые объекты, безопасные пропуски, критические ошибки, причины и
длительность. Занятый файл, отказ доступа, изменение после предпросмотра
и настоящий сбой имеют разные статусы.

Для передачи диагностики запустите **`SupportBundle.bat`** либо добавьте
`-CreateSupportBundle`. В ZIP попадут обезличенные копии последнего
текстового и JSONL-журнала, `config.json` и краткая информация о среде.
Имя пользователя, имя компьютера и пользовательские пути заменяются
маркерами; перед отправкой ZIP всё равно можно открыть и проверить.

**Важно про приватность:** у CleanupArchive нет сетевого кода — ни одна
строка проекта не открывает соединение и никуда ничего не отправляет.
Логи и отчёты лежат только локально в `logs\` и `reports\`. Если вам
нужна помощь в разборе ошибки — журнал придётся скопировать/переслать
самостоятельно (например, вставить в чат при следующем обращении за
помощью); никакой автоматической телеметрии или "звонка домой" в
проекте нет и не будет.

Стандартный предпросмотр перед вопросом Y/N не засоряет журнал реального
запуска. При отдельном запуске с `-WhatIf` результаты задач сохраняются,
чтобы получился полноценный диагностируемый отчёт без удаления данных.

## Требования

- Windows 10 или Windows 11 (x64/ARM64).
- Windows PowerShell 5.1 или новее (входит в состав Windows по умолчанию).
- Права администратора для самой очистки (запрашиваются автоматически
  через UAC в момент запуска Cleanup.ps1) — для веб-интерфейса настроек
  (`Settings.bat`) права администратора не нужны.
- Ничего дополнительного устанавливать не требуется: веб-интерфейс
  использует только встроенные в Windows компоненты (.NET
  `HttpListener` и браузер по умолчанию), без Node.js, Python или
  какого-либо стороннего рантайма.

## Дисклеймер

Программа изменяет файлы на вашем компьютере. Несмотря на многоуровневую
защиту системных каталогов и то, что удаляются исключительно
восстанавливаемые кэши и временные данные, автор(ы) проекта не несут
ответственности за возможные последствия использования. Внимательно
проверьте `config.json` перед первым запуском и используйте `logs\`,
чтобы увидеть, что именно было сделано.
